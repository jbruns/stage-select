# Stage Select 0.13.4

This release is about permission changes on your host. A permission or owner change no longer leaves placed games
stuck as conflicts, and a game you moved back by hand can be brought home with one audit. Stage Select's own
`.stage-select` folders are accepted when they belong to your group, and fixed rather than refused when others can
reach them.

## Upgrading

0.13.4 opens your 0.13.3 store and updates it in place. The update can't be undone: it fills in the SHA-256 of placed
files where an earlier audit already proved it, and backs up your store first, as every update does.

- A placed file's `sha256` is now known more often: after a rename, where the audit read the whole file, and after any
  check or audit that proves it again.
- A build, cleanup or ingest plan can now carry `repaired`, saying what Stage Select changed in the permissions of the
  folder's own `.stage-select` folders. It isn't part of what an approval binds, so plans made before 0.13.4 keep their
  digests.

## Changes you'll notice

- **A permission change no longer makes placed games conflicts.** A placed file whose permissions or owner changed is
  read again and proven: against its recorded SHA-256, or against the ROMs the build placed it as. If its bytes hold,
  it's refreshed, and you can return it, send it back or unregister the folder as before. A ZIP is proven by the
  bytes of its members, whichever tool compressed it. Its headers are taken as an audit takes them.
- **An audit refreshes your placed games.** An audit that verifies a placed file records its hash and stamp, so "audit
  the source set" now clears what it suggests.
- **Games you moved back by hand come home.** When an audit finds every ROM of a placed game back in your source set's
  own folder, and nothing of it where it was placed, it records the game as home. Only the store changes, and your
  next build places the game again. A library folder check that can't find a placed file says when the same file, or
  one of the same name, is in your source set.
- **Your `.stage-select` folders are accepted when your group can reach them.** A `.stage-select` folder, and each
  folder inside it, is used when Stage Select can read and write it and no one outside its owner and group has access,
  whoever owns it. Group bits and setgid are kept.
- **Stage Select closes its own folders.** When a `.stage-select` folder Stage Select owns is open to others, it removes
  that access itself, and the folder's next plan says so.
- **Refusals say how to fix them.** A `.stage-select` folder Stage Select can't use is refused with what's wrong, what's
  expected and the command to run on your host. The command uses the path as Stage Select sees it: if Stage Select
  runs in a container, use the host folder mounted there. Once you've fixed it, your next plan runs, with nothing left
  to clear and no restart.

## Fixes

- A placed game's files moved back to your source set by hand are no longer reported as the only copy missing, with
  every way out refused.
- A build that stopped because of a folder's permissions now retries its cleanup on your next plan, rather than asking
  for a restart.
