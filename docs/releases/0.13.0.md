# Stage Select 0.13.0

## Title Select is now Stage Select

This release renames the application to Stage Select, the ROM organizer. Every name it shows, writes or answers to
changes with it: the binary, the image, the environment variables, the metrics, the store's file, the folder it keeps
in each library folder and the version strings of its machine-readable output. The table below lists each one, old
beside new.

The repository moves too, from `jbruns/title-select` to `jbruns/stage-select`. GitHub redirects the old address, but
update your bookmarks and clones.

## The compatibility promise restarts here

0.12.0 promised that a store made by it would open in every later release, and that the API and the
machine-readable formats would change only with warning. The rename withdraws that promise once, here, and only here.

From 0.13.0 the promise starts again, on the same terms:

- A store opens in every later release: its migrations only ever add to what came before.
- Anything that will go away is announced as deprecated in at least one minor release first.
- A change that breaks a machine-readable format gets a new version of it: `/api/v2`, or a new `schema` string.
- Every release's notes list what it deprecates and what it removes.

## An earlier store is refused

0.13.0 opens no store made by an earlier release. Pointed at one, the service and the commands stop with:

> This store was made by an earlier release and can't be opened. Start a new store.

Nothing made before is adopted. Point `--store` (or `STAGE_SELECT_STORE`) at a new, empty directory, then register
your roots, DATs, source sets and library folders again, and audit them. Your earlier store is left as it was.

Every folder an earlier release managed, such as a library folder it built or a source set it repaired, keeps its
files and its `.title-select/` folder, with the folder's marker and any kept files. 0.13.0 doesn't treat that folder
as its own and manages none of it: make your library folders again and build them, and once you've moved out any
kept files you want, delete the old `.title-select/` folder yourself.

## What to change

Change these by hand, as nothing changes them for you:

- **Deployment:** the image, its entrypoint, and every environment variable.
- **Monitoring:** every metric name in your dashboards, alerts and recording rules.
- **Webhook receivers:** the two header names they read.
- **Scripts and integrations:** the binary's name, the `schema` strings and selection fields they check, and the
  `outcome` parameter of the selection releases endpoint.

collapsed, so after upgrading the workbench forgets those once.

## Also in this release

- The workbench wears Stage Select's new look, in light and dark, with its own fonts and icons served beside it. It
  requests nothing from any other origin.
- Screens share one shape: a title with its status, a strip of counts that filter, the list, and the reasons for
  each row beside it. Statuses, messages, tabs, plans and kept files each look and work the same everywhere.
- Job progress and a source set's games show on a segmented meter.
- First run and the settings say less and lead somewhere at every step.
- The README starts with a quick start for running the image.
