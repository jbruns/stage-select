# Stage Select 0.14.0

This release lets you say which permissions your games should have. You set a file mode, a folder mode and a group
once, or per root. Stage Select gives them to everything it writes, tells you where your files differ, and restores
what it can. Where its own access doesn't reach, it gives you the command to run on your host.

0.13.4 and 0.13.5 weren't published on their own, so 0.14.0 is the first release to include them. Their notes, in
`docs/releases/0.13.4.md` and `docs/releases/0.13.5.md`, list what they change: placed games recover from a permission
change and from a move by hand, `.stage-select` folders are accepted and fixed rather than refused, and a change of
permissions or owner alone no longer makes a source set stale.

## Upgrading

0.14.0 opens your 0.13.3 store and updates it in place. The update can't be undone: an earlier release won't open the
store afterwards. Your store is backed up first, as before every update. It fills in the SHA-256 of placed files where
an earlier audit proved it, and records which files changed only in permissions or owner. The upgrading notes of
0.13.4 and 0.13.5 list the fields it adds.

Your permission policy is kept with your other settings.

- Settings can now carry `permissions`: a `global` policy and per-root ones under `roots`, each with `file_mode`,
  `folder_mode` (octal strings such as `"0660"` and `"2770"`) and an optional numeric `group`.
- `GET /api/v1/source-sets/{name}/permissions` and `GET /api/v1/libraries/{id}/permissions` report what the latest
  check found differing from the policy. `POST` to `…/permissions/restore` with `{"digest": …}`, the digest you
  reviewed, restores it.

Nothing is deprecated or removed.

## Changes you'll notice

- **A permission policy.** Under Roots, set the file mode, the folder mode (setgid included) and an optional group for
  every root, and give any root its own instead. Without a policy, your host's defaults apply and nothing is reported.
  Stage Select refuses a policy that would lock it out of its own files, and a group it doesn't belong to.
- **What Stage Select writes comes out as you declared.** Builds, repairs, ingest moves and placements give each new
  file and folder your policy. Stage Select changes the mode only of files it owns, and the group only to a group it
  belongs to. Its own `.stage-select` folders keep their own rules.
- **Checks show where files differ.** A source set's check for changes and a library folder's check compare each file
  and folder with your policy, using what they already read. A difference shows on the new Permissions tab. It never
  makes a source set stale or a library folder drift, and never blocks an audit or a build.
- **Restore what Stage Select owns.** The Permissions tab lists what Stage Select can restore as a plan: review it, then
  approve it. A read-only source set is only reported.
- **What it can't fix, it explains.** Files another user owns, or that need a group Stage Select isn't in, are grouped by
  cause, each with what's wrong, what's expected and one command to run on your host. The command never reaches into
  `.stage-select`. Check again once you've run it.

## Known limits

- What a check finds is kept until Stage Select restarts. After a restart, check again.
- Ingest folders and additions aren't checked yet, and nor are subfolders nested inside a library folder.
