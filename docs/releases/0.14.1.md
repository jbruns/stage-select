# Stage Select 0.14.1

This release fixes library folders that read stale when nothing had changed. A build that placed games under single
copy, or returned them to your source set, made the folder stale at your next audit, and could make another folder
built from the same source set stale at once.

## Upgrading

0.14.1 opens your 0.14.0 store and updates it in place. The update can't be undone: an earlier release won't open the
store afterwards. Your store is backed up first, as before every update. The first start after the update works out
again what each audit you keep found, so it takes a little longer than usual. A library folder that reads stale only
because of this fix's bug reads fresh once it's done, with no build needed.

Nothing in the API changes.

## Fixes

- **Placing or returning games no longer makes library folders stale.** Whether a library folder is stale now
  depends on what your audits found, not where they found it. Placing a game, returning it to your source set, or
  writing it as a ZIP as it's placed moves files without changing what's found, so neither the folder that holds your
  games nor any other folder built from the same source set reads stale because of it. A ROM that's gone, or whose
  bytes changed, still makes it stale.

## Known limits

- A placed game you move back to your source set by hand doesn't make its library folder stale. Its check reports
  the game missing and says the file is in your source set; your next audit records it there, and your next build
  places it again.
- A game written as a ZIP whose files don't match its source's one for one can make a library folder built before it
  stale once. Building again clears it.
