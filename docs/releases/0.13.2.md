# Stage Select 0.13.2

This release follows more of your first run: a root's kind now says what it holds, a repair sets mismatched files
aside, and a repair plan shows where each game is now.

## Upgrading

0.13.2 opens your 0.13.1 store and updates it in place. One change isn't additive: the root kind `general` is gone,
and the API and CLI no longer take a root's writability.

- Each `general` root becomes `sources` if it was read-only, or `library` if it was writable. An empty root you
  meant for source sets but made writable becomes `library`: change its kind to `sources`.
- API clients registering or editing a root send `kind` as `sources`, `library`, `ingest` or `additions`, and no
  longer send `writable` or `writable_paths`; `general` is refused. Responses still show `writable` and
  `writable_paths`.
- The CLI's `--writable`, `--read-only`, `--writable-path` and `--no-writable-paths` are gone from `root register`
  and `root edit`; `--kind` takes the four kinds.

## Changes you'll notice

- **A root's kind says what it holds, and whether it's writable.** `sources` holds source sets and is read-only:
  Stage Select changes only the source sets you let it, with each one's switch. `library` holds play library folders
  and, like `ingest` and `additions`, is writable. You no longer choose writability, and forms offer only the roots
  of the kind they need.
- **A mismatched file is set aside by default.** A file under a ROM's name whose bytes match no ROM used to stay in
  your source set unless an ingest folder item could replace it. A repair now proposes setting it aside, into the
  source set's kept files, showing its size, CRC32 and SHA-1 beside the DAT's so you can spot a header difference or
  a dump from another DAT revision first. Its game then counts as missing until a later ingest fills it. A file under
  the name of a ROM with no good dump known, or of a game outside your coverage, is still left by default, and a ZIP
  that also holds ROMs the audit matched is only left.

## Fixes

- A repair plan shows where each game is now, rather than its new name, for every rename, repack, conversion, fill
  and replacement: "Now" and the change column read the files it's read from.
- After a repair, its follow-up audit's status shows once, under Audit, and still shows when you come back after it
  finished.
